======================================================================
US09 — AJOUT D’UN MOT DE PASSE À UN FICHIER
======================================================================

OBJECTIF

Permettre à un utilisateur connecté ou anonyme de protéger un fichier
par mot de passe lors de son envoi.

Règles de gestion : - mot de passe facultatif lors de l’upload ; - mot
de passe requis au téléchargement si le fichier est protégé ; - minimum
6 caractères ; - stockage uniquement sous forme hashée ; - aucun
mécanisme de récupération du mot de passe ; - fonctionnalité disponible
pour les utilisateurs connectés et anonymes.

====================================================================== 1.
BASE DE DONNÉES — POSTGRESQL
======================================================================

Table : stored_files

ALTER TABLE stored_files ADD COLUMN password_hash VARCHAR(255);

La colonne est nullable : un fichier peut donc rester sans protection.

2.2 UploadService.java — validation et hashage

Fichier :
backend/src/main/java/fr/datashare/backend/service/UploadService.java

Injection de PasswordEncoder :

private final PasswordEncoder passwordEncoder;

Import :

import org.springframework.security.crypto.password.PasswordEncoder;

Les méthodes upload(), uploadAnonymous() et processUpload() reçoivent
désormais un paramètre String password.

Validation et hashage :

private String resolvePasswordHash(String password) { if (password ==
null || password.isBlank()) { return null; }

    if (password.length() < 6) {
        throw new FileUploadException(
                "Le mot de passe doit contenir au moins 6 caractères."
        );
    }

    return passwordEncoder.encode(password);

}

Dans processUpload() :

String passwordHash = resolvePasswordHash(password);

Puis :

storedFile.setPasswordHash(passwordHash);

Un mot de passe absent produit donc passwordHash = null. Un mot de passe
valide est hashé avant l’enregistrement.

2.8 FileController.java — téléchargement

Le téléchargement passe de GET à POST afin de transmettre le mot de
passe dans le corps de la requête :

@PostMapping(“/{token}/file”) public ResponseEntity download(
@PathVariable String token, @RequestBody(required = false)
DownloadFileRequest request ) { String password = request == null ? null
: request.password();

    DownloadService.DownloadResource download =
            downloadService.loadDownloadFile(
                    token,
                    password
            );

    MediaType mediaType;

    try {
        mediaType = MediaType.parseMediaType(
                download.mimeType()
        );
    } catch (IllegalArgumentException exception) {
        mediaType = MediaType.APPLICATION_OCTET_STREAM;
    }

    ContentDisposition contentDisposition =
            ContentDisposition.attachment()
                    .filename(
                            download.originalName(),
                            StandardCharsets.UTF_8
                    )
                    .build();

    return ResponseEntity.ok()
            .contentType(mediaType)
            .header(
                    HttpHeaders.CONTENT_DISPOSITION,
                    contentDisposition.toString()
            )
            .body(download.resource());

}

3.5 files.ts — téléchargement protégé

Ajout :

protectedFileName =’’;

onDownload() vérifie file.passwordProtected.

Si false : - téléchargement immédiat.

Si true : - mémorisation du token et du nom ; - attente de la saisie du
mot de passe.

La méthode privée downloadFile() centralise l’appel au service et la

onProtectedDownload() transmet ensuite :

3.6 files.html / files.ts — utilisateur authentifié

Pour éviter le doublon entre un bouton « Télécharger » puis un bouton
« Valider », le téléchargement protégé utilise désormais un seul bouton.

Ajout d'une méthode de décision dans files.ts :

onDownloadClick(file: FileHistoryResponse): void {

    const passwordFieldIsOpen =
        file.passwordProtected &&
        this.protectedFileToken === file.downloadToken;

    if (passwordFieldIsOpen) {
        this.onProtectedDownload();
        return;
    }

    this.onDownload(file);
}

La méthode onDownload() conserve les responsabilités suivantes :

- fichier non protégé :
  téléchargement immédiat ;

- fichier protégé :
  mémorisation du token et du nom du fichier ;
  remise à zéro de downloadPassword ;
  affichage du champ de mot de passe.

Le template utilise ensuite un seul bouton :

<button
    type="button"
    class="download-button"
    [disabled]="
        file.passwordProtected &&
        protectedFileToken === file.downloadToken &&
        downloadPassword.length < 6
    "
    (click)="onDownloadClick(file)">
    Télécharger
</button>

Le premier clic sur Télécharger affiche le champ si le fichier est protégé.
Après saisie du mot de passe, le même bouton lance onProtectedDownload().


3.6.1 Gestion du mauvais mot de passe

InvalidFilePasswordException renvoie désormais HTTP 403 Forbidden et non
HTTP 401 Unauthorized, afin d'éviter que l'interceptor d'authentification
n'interprète l'erreur comme une session invalide.

Dans GlobalExceptionHandler :

@ExceptionHandler(InvalidFilePasswordException.class)
public ResponseEntity<String> handleInvalidFilePassword(
        InvalidFilePasswordException exception
) {
    return ResponseEntity
            .status(HttpStatus.FORBIDDEN)
            .body(exception.getMessage());
}

Dans files.ts :

error: error => {
    console.error(
        'Erreur lors du téléchargement :',
        error
    );

    this.errorMessage =
        error.status === 403
            ? 'Mot de passe incorrect.'
            : 'Impossible de télécharger le fichier.';

    this.changeDetectorRef.markForCheck();
}

Le message est affiché sous le champ de mot de passe du fichier concerné.
Le champ et le message sont regroupés dans un conteneur password-download
afin d'éviter de déformer la ligne du fichier.

4. FLUX FONCTIONNEL
======================================================================

UPLOAD PROTÉGÉ

Mot de passe ↓ Validation minimum 6 caractères ↓
PasswordEncoder.encode() ↓ Hash enregistré dans
stored_files.password_hash ↓ Mot de passe original non conservé

TÉLÉCHARGEMENT PROTÉGÉ

Clic sur Télécharger ↓ passwordProtected = true ↓ Affichage du champ de
mot de passe ↓ POST /api/files/{token}/file ↓ DownloadFileRequest ↓
PasswordEncoder.matches() ↓ Mot de passe correct → téléchargement Mot de
passe incorrect → HTTP 403

8. RÉSULTAT FINAL
======================================================================

L’US09 permet aux utilisateurs connectés et anonymes de protéger leurs
fichiers par mot de passe.

Le mot de passe : - est facultatif à l’upload ; - comporte au minimum 6
caractères lorsqu’il est renseigné ; - est stocké uniquement sous forme
hashée ; - est vérifié lors du téléchargement ; - n’est jamais exposé au
frontend sous forme de hash.

Le frontend reçoit uniquement l’information passwordProtected.

Les fichiers non protégés conservent leur téléchargement direct.

- onLogout() redirige vers '/'.
