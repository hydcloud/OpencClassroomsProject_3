--- files.service.ts --------------------------------------------------

Création d'une méthode privée sendFile()

  private sendFile(
    url: string,
    file: File,
    expirationDays: number
  ): Observable<FileUploadResponse> {
    const formData = new FormData();

    formData.append('file', file);
    formData.append(
      'expirationDays',
      expirationDays.toString()
    );

    return this.http.post<FileUploadResponse>(
      url,
      formData
    );
  }

Cette méthode sera retournée par la méthode upload() et la nouvelle méthode uploadAnonymous()

  upload(
    file: File,
    expirationDays: number
  ): Observable<FileUploadResponse> {
    return this.sendFile(
      this.apiUrl,
      file,
      expirationDays
    );
  }

  uploadAnonymous(
    file: File,
    expirationDays: number
  ): Observable<FileUploadResponse> {
    return this.sendFile(
      `${this.apiUrl}/anonymous`,
      file,
      expirationDays
    );
  }

Puis on sépare la méthode commune privée processUpload() : 
    private FileUploadResponse processUpload(
            MultipartFile file,
            int expirationDays,
            User owner
    ) {
        validateFile(file);
        validateExpiration(expirationDays);

        LocalDateTime expiresAt =
                LocalDateTime.now().plusDays(expirationDays);

        String storageName =
                storageService.store(file);

        try {
            StoredFile storedFile = new StoredFile();

            storedFile.setOriginalName(resolveOriginalName(file));
            storedFile.setStorageName(storageName);
            storedFile.setMimeType(resolveMimeType(file));
            storedFile.setSize(file.getSize());
            storedFile.setExpiresAt(expiresAt);
            storedFile.setOwner(owner);

            StoredFile savedFile =
                    storedFileRepository.save(storedFile);

            DownloadLink savedLink =
                    downloadLinkService.createLink(
                            savedFile,
                            expiresAt
                    );

            return new FileUploadResponse(
                    savedFile.getId(),
                    savedFile.getOriginalName(),
                    savedFile.getMimeType(),
                    savedFile.getSize(),
                    savedFile.getUploadedAt(),
                    savedFile.getExpiresAt(),
                    savedLink.getToken(),
                    "/api/files/" + savedLink.getToken() + "/file"
            );

        } catch (RuntimeException exception) {
            storageService.delete(storageName);

            throw new FileUploadException(
                    "L'enregistrement du fichier a échoué.",
                    exception
            );
        }
    }

Ajout de l'endpoint relatif à upload-anonymous : 

    @PostMapping("/anonymous")
    public ResponseEntity<FileUploadResponse> uploadAnonymous(
            @RequestParam("file") MultipartFile file,
            @RequestParam(
                    name = "expirationDays",
                    defaultValue = "7"
            ) int expirationDays
    ) {
        FileUploadResponse response =
                uploadService.uploadAnonymous(
                        file,
                        expirationDays
                );

        return ResponseEntity
                .status(HttpStatus.CREATED)
                .body(response);
    }

US07 — Ajout de l'upload anonyme

Objectif :
Permettre à un utilisateur non authentifié d'envoyer un fichier et d'obtenir
un lien de téléchargement, sans rattacher le fichier à un compte utilisateur.

BACKEND

- Modification de StoredFile afin de rendre la relation avec User facultative.
  → Un fichier authentifié possède un user_id.
  → Un fichier anonyme possède user_id = NULL.

- Modification de UploadService :
  → conservation de upload() pour les utilisateurs authentifiés.
  → ajout de uploadAnonymous() pour les utilisateurs anonymes.
  → factorisation du traitement commun de l'upload dans une méthode privée.
  → l'upload anonyme ne recherche/ne rattache aucun User.

- Modification de FileController :
  → POST /api/files : upload authentifié.
  → POST /api/files/anonymous : upload anonyme.

- Modification de SecurityConfig :
  → POST /api/files/anonymous autorisé sans authentification.
  → POST /api/files reste protégé par JWT.
  → le téléchargement par token reste accessible publiquement.

FRONTEND ANGULAR

- Modification de la route d'accueil :
  → la page principale est désormais accessible sans authentification.
  → le login reste accessible depuis l'interface.

- Modification de FilesService :
  → upload() utilise POST /api/files.
  → ajout de uploadAnonymous() utilisant POST /api/files/anonymous.
  → factorisation de la création du FormData et du POST dans sendFile().

- Modification du composant Files :
  → vérification de l'état d'authentification avec AuthService.
  → utilisateur connecté : appel de upload().
  → utilisateur anonyme : appel de uploadAnonymous().
  → l'historique n'est chargé que pour un utilisateur authentifié.
  → récupération du downloadToken/downloadUrl après un upload anonyme.

- Modification de FileUploadResponse :
  → ajout de downloadToken et downloadUrl correspondant aux données
    retournées par le backend.

- Modification de l'interface :
  → l'upload reste visible pour tous.
  → "Mes fichiers" est uniquement visible pour un utilisateur connecté.
  → un utilisateur anonyme voit les liens Se connecter / Créer un compte.
  → après un upload anonyme, le lien de téléchargement généré est affiché.
  → aucun historique ni gestion du fichier n'est proposé à l'anonyme.
